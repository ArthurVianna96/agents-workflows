# Hand off work

## Purpose

Transfer a task between people, agents, or sessions without losing the context required to continue safely.

## When to use

Use at the end of planning, implementation, review, investigation, or any session that another person will continue.

## Required context

- The current task state and intended outcome.
- Decisions made, work completed, validation performed, and unresolved concerns.
- The recipient’s likely next responsibility.

## Workflow

1. Summarize the goal and current status in plain language.
2. Record decisions and their rationale, including assumptions that remain relevant.
3. List files changed or examined and describe the meaningful changes.
4. Record commands, tests, checks, or manual validation and their results.
5. Call out risks, blockers, and work deliberately left undone.
6. State one concrete next action and who or what role should take it.

## Expected output

Use this handoff contract:

```text
Task goal:
Decisions:
Files changed:
Validation performed:
Remaining risks:
Next action:
```

## Completion criteria

A new person or fresh session can understand the task state, verify what happened, and take the named next action without relying on unstated context.
